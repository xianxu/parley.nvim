# Parley shipping-surface inventory (#206, feeds #162 / #207)

**Date:** 2026-09-02
**Purpose:** Decide what parley ships, emphasizes, gates, or deletes before a wide
public announcement. Produced by a three-cluster code audit (chat core /
providers+tools / discovery+workflow) plus a clean-clone install repro.

Every claim below carries a `file:line`. The P0 was reproduced directly, not inferred.

---

## Tier 0 — Launch blockers

These are not documentation problems. Announcing before they are fixed converts a
launch into an incident.

### B1. A clean clone does not load. (verified by repro)

`require("parley")` raises on any machine that is not the author's:

```
issue_vocabulary.lua:147: failed to read issue vocabulary:
  <cwd>/construct/generated/vocabulary/issue.json
```

- `init.lua:110-111` calls `issues_mod.setup(M)` at **module top level**.
- `issues.lua:23-26` calls `issue_vocabulary.default()` → `load()` → `error()`
  (`issue_vocabulary.lua:138-156`).
- The file is `construct/generated/vocabulary/issue.json`
  (`issue_vocabulary.lua:5`), gitignored at `.gitignore:43`, generated by a cue
  export from the **ariadne sibling repo** (`scripts/setup-construct.sh`).
- `git archive HEAD | tar -x` into a fresh dir and requiring the plugin reproduces
  the error. A `lazy.nvim` clone hits the same path.

**Root cause is the ariadne coupling, not a packaging slip.** The public plugin
cannot load because of an issue-tracker vocabulary that public users have no use
for. This puts #162 (split parley from ariadne) on the critical path to the
announcement rather than beside it.

Minimum fix: make vocabulary load lazy and failure non-fatal. Correct fix: the
#162 split.

### B2. The model can read every sibling directory by default.

`tool_read_roots = {'../'}` (`config.lua:294`) — the parent of cwd. Read tools are
confined to cwd ∪ `tool_read_roots` (`tools/dispatcher.lua:129`), so out of the
box an agent can read every sibling repo and directory on disk. Undocumented in
README.

### B3. Write tools are on by default, unconfirmed, and untested.

- The one shipped agent has `tools = { "@all" }` (`config.lua:226`); `@all`
  expands to include `kind = "write"` (`tools/init.lua:99-101`).
- Picking any live cliproxy model in the agent picker also grants `@all`
  (`cliproxy_catalog.lua:238`) with no UI hint that the row is write-capable.
- **No confirmation prompt exists anywhere** — grep for `confirm|vim.ui.select`
  across `lua/parley/tools/` returns nothing.
- `edit_file` has `needs_backup = false` and **zero behavioral tests**; no
  `tools_builtin_edit_file_spec.lua` exists. `write_file`'s handler is likewise
  untested.
- The tool loop runs up to **42 unattended iterations** (`defaults.lua:71`).
- `.parley-backup.<n>` files accumulate unboundedly (`tools/backup.lua:17-33`),
  are never cleaned, and are not gitignored.

### B4. Startup ships the user's chat archive to a third party, unprompted.

`memory_prefs.enable = true`, `max_age_days = 1` (`config.lua:493`), triggered
from `setup()` via `maybe_generate()` (`init.lua:1199`). On a fresh install it
shells `grep -r` across every chat root, sends summaries of up to 100 files per
tag to the model, and writes generated `.md` files back into `chat_dir`.

### B5. Unprompted third-party binary download, on the main loop.

`cliproxy.manage = true` + `auto_download = true` (`config.lua:117,120`) fetch a
GitHub release tarball, sha256-verify, extract and `chmod 755` a binary
(`cliproxy.lua:721-731, 1758-1845`).

- Runs **synchronously on the main loop** with a 300s `--max-time`
  (`cliproxy.lua:1810-1817`) — a slow network freezes the editor.
- Pinned to `7.1.71` (`cliproxy.lua:1762`), which the code elsewhere already
  treats as stale (`cliproxy.lua:911`: "7.2.110 dropped `-login`").
- `checksums.txt` comes from the same origin as the tarball: integrity, not
  authenticity.
- `config.lua:122-124` already concedes "a general distribution may prefer to
  comment this out". The shipped config does not.

### B6. Personal configuration ships as product defaults.

| Default | Value | Where |
|---|---|---|
| `chat_dir` | `~/Library/Mobile Documents/…/parley` | `config.lua:259` |
| `notes_dir` | `~/Library/Mobile Documents/…/notes` | `config.lua:265` |
| `export_html_dir` | `~/blogs/static` | `config.lua:273` |
| `export_markdown_dir` | `~/blogs/posts` | `config.lua:274` |
| notes path | **hardcoded in code, not config** | `lualine.lua:138,184` |
| voice skill source | `~/.personal/<slug>-writing-style.md` | `skills/voice_apply/init.lua:8,44` |

The `_dir$` sweep at `init.lua:725-728` **auto-creates** these at setup, so every
fresh install silently mkdir's `~/blogs/` and, on Linux, a literal
`~/Library/Mobile Documents/...` directory. `exporter.lua:922` shells `open -R`.

### B7. The repo ships the author's private workshop.

`.parley` and `.ariadne-mode` are git-tracked, along with ~370 files under
`workshop/` — 338 archived issue records and **11 real chat transcripts** in
`workshop/parley/`, plus `pensive/` and `continuation/`.

### B8. Shipped prompt text points at a file the user does not have.

`skills/review/SKILL.md:1` links the marker grammar to
`../../../../ariadne/workshop/targets/review-convention.md`, a path in a sibling
repo that does not ship. That SKILL.md is sent to the model as system prompt.
`drill_in.lua:31,514` names the same out-of-repo spec as normative for `<M-q>`.

### B9. Keybinding land-grab.

`init.lua:851-852` calls `register_global` with a **literal** scope list
`{ "global", "repo", "note", "issue", "vision", "chat" }` — never filtered by
`.parley` presence. So for every user, in normal *and* insert mode:

- `<C-y>c/f/x/s/i/g` (issues) and `<C-j>f/n/o/v/ec/ed/ea` (vision) are bound
  though the features are inert
- `<C-n>i` / `<C-n>I` (interview) are bound globally, hardcoded, not rebindable
  (`keybinding_registry.lua:305-318`)
- four `<leader>c*` maps are claimed in every buffer (`config.lua:356-359`), with
  **zero tests** for `parley.copy`
- `<CR>` is rebound in insert mode in chat buffers by spell typeahead
  (`config.lua:312-320`) — collides with cmp/blink, no runtime toggle
- `u` and `<C-r>` are shadowed in chat buffers with no opt-out
  (`init.lua:2190-2218`)
- `gf` is shadowed in every parley buffer; `BARE_PAT = "#%d+"`
  (`artifact_ref.lua:20`) means a plain `#42` in prose routes to a nonexistent
  `sdlc` and surfaces a raw shell error instead of falling through to native `gf`
  (`init.lua:4294-4297`)

Meanwhile `<C-g>?` **hides** those bindings outside a repo
(`keybinding_registry.lua:66-68`): help and reality disagree in both directions.

### B10. `:checkhealth parley` reports green on a broken install.

43 lines (`health.lua:7-42`) checking `require`, `setup()`, `curl`, lualine. It
does not check `git`, `rg`, `pandoc`, `sdlc`, the API key, the cliproxy binary, or
the missing vocabulary JSON that hard-fails the plugin (B1).

## Tier 1 — Ship and lead with

This is the announcement story. Each item is reachable, tested, and works without
ariadne.

| Feature | Reach | Coverage |
|---|---|---|
| Markdown transcript as full chat state; edit anything, including the model's replies | — | `parse_chat_spec` (54), `exchange_model_spec` (28) |
| Respond + streaming, one undo step per answer | `<C-g><C-g>`, `<M-CR>` | `chat_respond_spec` (65), `sse_parsing_spec` (47) |
| Tree of chats — branch out a sub-thread, keep the path as context | `<C-g>b`, `<C-g>i` | `inline_branch_spec` (15) ⚠ prune happy path untested |
| Quote-and-comment a reply, gathered into the next turn | `<M-q>` → `🤖<T>[Q]` | `drill_in_spec` (113) |
| Inline term definition as a managed footnote | select + `<M-CR>` | `define_spec` (41+27) |
| Chat finder over every root | `<C-g>f` | `chat_finder_logic_spec` (48), `float_picker_spec` (77) |
| Vendor neutrality — mix providers in one conversation | `<C-g>a` | per-provider wire specs |
| Use a Claude/Codex subscription via cliproxyapi, no API key | `:ParleyProxy login` | ~340 assertions, best-covered area |
| Live model picker — catalog, not a hand-maintained list | `<C-g>a`, `<C-a>` | `cliproxy_catalog_spec` (54+22) |
| File context | `@@path@@` | `remote_references_spec` (11) |
| Local tools — read/grep/ls/find, and search your own chat history | — | `tools_dispatcher_spec` (57) |
| Server-side web search | `<C-g>w` | partial |
| Export chat tree to Markdown or HTML | `<C-g>em`, `<C-g>eh` | `exporter_tree_spec` (24) |

**Note the syntax correction:** the canonical file reference is `@@path@@` with
**both** delimiters, and the ref must start with `https://`, `/`, `~/`, `./` or
`../` (`chat_parser.lua:497-512`). README's `@@path/to/file` is the open form,
which opens under the cursor but is **never sent to the model**.

## Tier 2 — Ship, do not lead with

Works; secondary to the story. Several need a default flipped before launch.

- Notes system + note finder (`<C-n>c/f/t/r/h`) — note creation itself untested
- Outline (`<C-g>t`), follow-cursor (`<C-g>l`), tool folds (60+ tests, **toggle
  unbound by default** — `config.lua:334-336`)
- Chat memory windowing (`max_full_exchanges = 42`) — default-on history rewriting
- Exchange cut/paste (`<C-g>X`/`<C-g>V`), `:ParleyChatMove`, `:ParleyChatReview`
  — all destructive, all thin or zero coverage
- Interview mode, raw-mode logging (**unbound** despite `init.lua:1170`'s comment
  claiming otherwise), lualine, copy helpers, markdown finder, system prompts
- Spell typeahead — flip default off or add a toggle (B9)

## Tier 3 — Gate behind the #162 split

Dead or broken for anyone not using an ariadne repo. What a plain user sees:

| Feature | Plain-install behavior | Code |
|---|---|---|
| Issue finder `<C-y>f` | **Empty picker**, no error — `issues_dir` always resolves against git root so the guard can't fire | `issues.lua:474-476`, `issue_finder.lua:359-365` |
| New issue `<C-y>c` | Prompt, spinner, then `Issue creation failed:` (no `sdlc`) | `issues.lua:752-776` |
| Vision finder `<C-j>f` | **Empty picker**, no error | `vision_finder.lua:53` |
| Vision export | Writes empty `roadmap.csv`/`roadmap.dot` **into their git root** | `vision.lua:1626-1631` |
| Review finder `<C-g>vf` | "not in a parley-enabled repo" | `skills/review/init.lua:394-397` |
| Super-repo `<C-g>p` | "cwd is not inside a .parley repo" | `super_repo.lua:113-117` |
| `gf` / `gP` on a ref | `sdlc` not found, native `gf` not attempted | `artifact_ref.lua:115-131` |

Weight being carried: `vision.lua` 2046 loc + 143 tests for a private roadmap
schema; `issues.lua` 963 loc + 102 tests. `vision` also registers a global
`BufRead *.yaml` autocmd that **disables nvim-cmp** for matching buffers
(`init.lua:929-951`).

Repo mode itself (`.parley` marker) is a reasonable generic idea; the `workshop/`
layout it imposes is ariadne's. It creates five directories in the user's repo on
first activation (`repo_artifacts.lua:3-9`).

## Also worth fixing

- **Google Drive is advertised but silently inert.** README:34 sells it;
  `client_id`/`client_secret` ship empty (`config.lua:49-53`), the flow aborts
  with only a `logger.warning` (`oauth.lua:1529-1532`), and making it work
  requires the user to register their own Google Cloud OAuth client — documented
  nowhere. 2464 loc + 110 tests behind a feature nobody can turn on.
- `review_agent` / `skill_agent` = `"Claude-Sonnet"` (`config.lua:385,390`), an
  agent that **does not exist** in the shipped config; resolution silently falls
  through to "first tool-capable agent" (`skill_assembly.lua:96-106`).
- An agent naming an unknown provider is deleted **silently**
  (`init.lua:773-774`); an unknown tool name `error()`s loudly (`:766-768`).
- Unknown provider names silently fall back to the OpenAI adapter, logged at
  `debug` only (`providers.lua:1335`) — a typo becomes an OpenAI-shaped request.
- `ack` registers only if the binary is on PATH (`tools/init.lua:174-178`), so the
  tool list the model sees is machine-dependent.
- `chat_history_search` **deliberately bypasses** the cwd-scope guard by passing no
  path (`chat_history_search.lua:6-8`).
- `log_sensitive` is off by default, but `:ParleyInspectPlugin` masks only the
  legacy `openai_api_key` field, **not the `api_keys` table**
  (`config.lua:573-574`) — it dumps resolved keys into a scratch buffer.
- Raw-mode logs write verbatim prompt/response bodies into `chat_dir`, i.e. iCloud
  by default; `.parley-logs/` is not gitignored for repo-mode chats.
- `~/.config/parley/skills/*/init.lua` is `loadfile()`d and executed
  (`skill_providers.lua:154-160`) — pcall-guarded but fully trusted.

## Health signals worth keeping

- 50,346 loc of plugin against **59,506 loc of tests in 200 spec files**.
- A full `TODO|FIXME|XXX|HACK` sweep of `lua/parley/` returns **two** hits, neither
  functional. The incompleteness here is structural, not abandoned.
- Keybindings have a real single source (`keybinding_registry.lua`) where help and
  registration both derive from one table, so they cannot drift. **Commands have
  no such seam** — they are ad-hoc `M.cmd.X = …` assignments scattered across
  `init.lua`, which is exactly why the command list rotted and the key list did
  not. 63 commands ship; ~20 are in the README.
- Dev energy is concentrated where the product is: `chat_respond`, `cliproxy`,
  `float_picker`, `chat_parser`, `providers`, `agent_picker`, `config` all moved
  2026-09-01. The ariadne surface is comparatively cold — `vision.lua`
  2026-06-20, `oauth.lua` 2026-03-07.
- Ariadne coupling is concentrated and therefore separable: `issues.lua` (82
  refs), `vision.lua`, `super_repo.lua`, `neighborhood.lua`, `artifact_ref.lua`
  and the two finders. The chat core sits at 0–6 refs. `init.lua` (71 refs) is the
  wiring hub that entangles them.

## Recommended sequence

1. **B1** — make the vocabulary load lazy and non-fatal. Nothing else matters
   until a clean clone loads.
2. **B2–B5** — flip the unsafe defaults: `tool_read_roots`, `@all` → `@readonly`
   (or add confirmation), `memory_prefs.enable = false`, `auto_download = false`.
3. **B6–B7** — strip personal paths and private content out of the shipped
   product.
4. **B9–B10** — scope the keybinding registration to what is actually live; make
   health check what actually breaks.
5. **#162** — split the ariadne surface (Tier 3) out. B1 is a symptom of not
   having done this.
6. **Tier 4** deletions.
7. **Then** rebuild the README around Tier 1 (#206) and script the video (#207).
