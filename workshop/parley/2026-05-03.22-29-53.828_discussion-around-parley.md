This is **Parley.nvim**, a Neovim plugin written in Lua.

### What it is

A **chat notebook for LLM conversations** inside Neovim. The core idea from the author: markdown as state, nvim/coding agent as the human operator interface. Chats are plain Markdown files — the transcript file *is* the full state of the conversation, so you can edit anything (including the LLM's own responses) to steer future replies.

### Design philosophy

Keep it **simple, local, and Unix-y**:
- Chats live as plain `.md` files you can edit anywhere
- Highly configurable, good defaults out of the box
- Keyboard-first, fast, minimal dependencies (just API keys)
- Predictable behavior across providers

### Distinguishing features

- **Multi-provider** — OpenAI, Anthropic, Google AI, Ollama, and you can mix providers in the *same* conversation
- **Tree of chats** — branch a side topic into a linked-but-separate file, rather than being forced into linear conversation, and jump between branches
- **Instant Chat Finder** (`<C-g>f`) to switch threads anywhere
- **Local file + Google Drive (oauth) access** in chats
- **Export** to Markdown/HTML for blogging/sharing
- **Raw request/response mode** as a learning tool for LLM interactions

### Codebase structure

The bulk is in `lua/parley/` — a large, modular codebase (100+ files). Rough functional groupings I can see:
- **Chat lifecycle**: `chat_respond.lua`, `chat_parser.lua`, `chat_finder.lua`, `chat_history.lua`, `render*.lua`
- **Providers/transport**: `providers.lua`, `provider_params.lua`, `sse.lua`, `dispatcher.lua`, `cliproxy*.lua`
- **Skills/tools/agents**: `skill_*.lua`, `tool_*.lua`, `tools/`, `agent_*.lua`
- **Finders**: `finder_*.lua`, `*_finder.lua` (chat, issue, note, vision, markdown)
- **Integrations**: `google_drive.lua`, `oauth.lua`, `lualine.lua`

There's also substantial supporting material: `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` (identical 15KB agent-instruction files), `docs/`, `tests/`, and a `Makefile.parley` with a perf-testing harness (`make perf`).
