# Breadcrumb winbar

The winbar names where a file is, never how the window reached it (#391). A side doc (a file with `parent:` frontmatter, or a tree root with `discussions:`) shows its tree path: the `parent:` chain from the root down to it, so with A > B1 > C1 and A > B2 > C2, jumping from C2 to C1 shows A › B1 › C1. The chain reads frontmatter only (the loaded buffer as edited, else the file's first 200 lines), and each file's parse is cached by path plus mtime, or by changedtick for a loaded buffer, in a 256-entry table that resets when full. The chain is bounded: a missing or unreadable parent, a cycle and more than 32 ancestors each end it with a lead marker (`?`, `↻`, `…`). Every other file shows its own path, one segment per directory, relative to the nearest `.git` root, else `~`, else `/`. A tree root and a repo-top file show one segment. Both values are recomputed whenever a window enters a file and the band repaints when the value changes, so a frontmatter edit shows on re-entry; they die with the window. `side_tree_model.parse` reads top-level keys only, since an indented key belongs to a `discussions:` entry. Because every file window carries the band, a user's own winbar (from a winbar plugin, say) is replaced in file windows and returns only when the window stops showing a file. `breadcrumb = { enable = false }` opts out: file windows then show the band only while a lock state does.

Alt+o still records a navigation trail after a successful file landing, but it is never displayed: it backs Alt+Shift+O and the snapshot contract. The trail belongs to the destination window; another window showing the same file can have a different trail. Failed, cancelled and stale resolver completions cannot turn a later file open into a followed link.

The shared [document band](../modes/session_sync.md) starts with a nine-column lock cell: `free`, `yours ●`, `stale`, `agent…` or `unknown`. The dot is evidence of unsubmitted content relative to the acquisition baseline, including after auto-save. A lock whose baseline is unknown shows `yours` without a dot. Receipt/error text follows the cell and trail; it never hides the lock or changes its background highlight. Coordinator notices are overlays on an attached state owner; without one, proven-plain and unknown membership supply a blank or unknown cell. State refreshes preserve the notice until its owner clears it. Main’s finite leave reminder is a priority feedback layer: it keeps the destination cell and trail, and a new split removes only the copied transient frame.

Labels are basenames without `.md` or a `YYYY-MM-DD-` prefix. Duplicate labels gain enough parent components to distinguish them. When stripping a date prefix makes two files in the same directory indistinguishable, their original paths provide the final disambiguation. Long paths collapse their middle to `…`, keeping the first segment and last two where space permits. Narrow windows preserve the lock cell before shortening the leaf; feedback takes space ahead of older segments. Literal path text cannot execute statusline expressions.

An ordinary file change (`:edit`, native `gf`, a finder) starts a new trail root. Alt+Shift+O still traverses the existing native file history and restores each visit's cursor and trail. It can reach an older unrelated root after the followed chain is exhausted. Same-file reloads preserve the trail. Native splits inherit an independent value, and closed windows release their history.

## Snapshot contract

`require("parley.file_history").snapshot(win)` returns a detached, opaque, JSON-safe value, or `nil, reason` when no valid named-file trail can be captured. Consumers store it verbatim. Window 0 means the current window.

`restore(win, value)` installs the trail and matching Back entries AFTER the caller opens the selected file. It returns `true`, or `false, reason`. It opens no files. Its last canonical path must match the actual opened file; malformed/unsupported/oversized values refuse before mutation. Genuinely missing ancestors are removed; uncertain filesystem failures refuse rather than claim absence. The surviving leaf alone becomes a root. The current cursor stays; unknown ancestor cursors start at row 1/column 0. On refusal a finder can keep the file it just opened as its ordinary root.

Values and histories are bounded to 200 paths/visits and 1 MiB per exported trail. Overflow retains the root and newest suffix with an omitted-count marker. There is no persistent trail store or background process. `peek(win)` is an internal cached detached read of the trail; it does no filesystem observation. `display(win)` is what the band paints: the tree or file path computed at the window's last observation, behind the same presentation proof. A presentation proof binds it to the observed eligible buffer/name in an editing window. Unnamed, special-buftype, URI, directory and non-editing windows retire the trail while preserving native Back history. Eligible re-entry restores presentation; copied float options unwind only while the installation proof matches.

## Code and tests

- `breadcrumb_model.lua`: pure transitions, validation, file-path values and display projection.
- `side_tree_model.lua`: pure, bounded `parent:` chain with an injected frontmatter reader.
- `file_history_model.lua` / `file_history.lua`: visit/cursor ownership, atomic ancestry installation and native navigation.
- `document_band_model.lua` / `document_band.lua`: pure composition and shared window option ownership/restoration.
- `display_text.lua`: Neovim display-unit adapter shared with the float picker; truncation retains each base character with its composing marks.
- `make -k test-spec SPEC=ui/breadcrumb`, `ui/keybindings`, `context/file_references` and `modes/session_sync` cover the model and native/fake-backed integration.
